# 画面と図の見た目の判定基準

> この文書は [`AGENTS.md`](../../AGENTS.md) の索引と [図の規格](architecture-diagrams.md) から読みます。食い違いがあれば `AGENTS.md` を優先します。
> 散文の判定は [文書品質の判定基準](writing-quality.md) が扱います。この文書が扱うのは、図、カバー画像、Web 画面の見た目です。
> 一部の項目は、公開されている UI 向けのスキル集を参考に書き直したものです。出典と変更点は [末尾](#出典と変更点) にあります。

## 適用範囲

Hub には Web 画面のソースがありません。見た目を持つ成果物は、生成した図（draw.io、SVG、PNG）とカバー画像です。
Web 画面を持つのは Spoke です。Spoke には [移植用の検査スクリプト](../../tools/portable/check-ui/check-ui.mjs) を渡します。

## 取り込んだ項目と取り込まなかった項目

| 項目 | 扱い | 理由 |
|---|---|---|
| 色の基調、グラデーション、光る影、絵文字のアイコン | 取り込む | ソースの文字列から機械的に判定できる |
| コントラスト比の下限、余白の刻み、動きの種類 | 取り込む | 数値で判定できる |
| 日本語の組版（行間、約物、太さ、斜体） | 取り込む | Spoke の日本語画面に適用できる |
| 画面の文言（感嘆符、待機メッセージ、煽り語） | 検査スクリプトにのみ取り込む | 散文は `ai-style` の規則が別に扱う |
| ログイン方式（パスキー前提など）、人前で操作する画面の作法 | 取り込まない | 作者の運用上の選択で、機械的に判定できない |
| ダークテーマは頼まれたときだけ | 取り込まない | 図は明暗の両テーマを出す規格で、逆の前提になる |
| iOS Simulator での確認手順 | 参照のみ | Hub に Web 画面がなく、手順の検証もしていない |

## 色とコントラスト

文字色と地の色の明度比は、本文で 4.5 以上、大きい太字で 3 以上を下限にします。
罫線と枠は 1.5 から 3 の範囲で、区切りが見えれば足ります。
明度比は目視で判断せず、計算で出します。

```python
def lin(c):
    c /= 255
    return c / 12.92 if c <= 0.03928 else ((c + 0.055) / 1.055) ** 2.4

def luminance(hex_color):
    h = hex_color.lstrip("#")
    r, g, b = (int(h[i:i + 2], 16) for i in (0, 2, 4))
    return 0.2126 * lin(r) + 0.7152 * lin(g) + 0.0722 * lin(b)

def ratio(a, b):
    hi, lo = sorted((luminance(a), luminance(b)), reverse=True)
    return (hi + 0.05) / (lo + 0.05)
```

`tools/build_diagrams.py` の配色を 2026-11-10 に計算した結果は次のとおりです。

| 組み合わせ | 明度比 | 下限 |
|---|---|---|
| ライト: 文字 `#232F3E` と地 `#FFFFFF` | 13.6 | 4.5 |
| ダーク: 文字 `#FFFFFF` と地 `#232F3E` | 13.6 | 4.5 |
| ライト: 補助線 `#B0B8C1` と地 `#FFFFFF` | 2.0 | 1.5 |

補助線は文字ではないので、下限は罫線の 1.5 を当てています。

## 図に既にある強制

図は仕様から生成するので、下の項目の多くは生成器が固定しています。手で編集した場合にだけ崩れます。

| 見た目の規則 | 図での担保 |
|---|---|
| 基調色は 1 つ、色分けに意味を持たせない | 配色は `Palette`（ライトとダーク）の 2 組だけ。矢印は単色の開いた矢印のみ |
| グラデーション、影を使わない | 生成器が `gradientColor=none` と `shadow="0"` を出力する。`make diagrams-check` が手編集を検出する |
| 文字の大きさの下限 | `make diagram-fonts` |
| 矢印は右か下へ進む | `make diagram-flow` |

`make diagrams-check` はアイコンパッケージが要るので `make all` には入っていません。
2026-11-10 に、`docs/_assets/` の draw.io 40 本と SVG 40 本を走査しました。
グラデーション、フィルタ、影の有効化、絵文字のいずれも 0 件でした。
追加の検査を足しても何も検出しないため、`make all` に新しい検査は足していません。

## 画面の規則（Spoke の Web 画面向け）

検査スクリプトが拾う型と、直し方の方向を示します。

| 型 | 直し方の方向 |
|---|---|
| カードの 1 辺だけの太い色線 | 面、角丸、細い枠で作り、状態は小さな丸か文字で示す |
| 絵文字をアイコン代わりに並べる | 線のアイコン素材を 1 種類だけ使う。要らなければ置かない |
| 文字のグラデーション、紫から桃色の広いグラデーション | 単色にする。強い色は意味のある 1〜2 か所に限る |
| 色の付いた光る影 | 地の明るさの差と細い線で奥行きを作る |
| `transition: all`、ホバーでの拡大、常時の点滅 | 動かす性質を指定する。ホバーは地の色を 1 段変えるだけにする |
| 極太（800 以上）、斜体、大文字で字間を広げたラベル | 太さは 400 と 600〜700 の 2 段。日本語の画面に斜体と字間の飾りは持ち込まない |
| 4px の刻みから外れた余白 | 4px の倍数にそろえる |
| 16px 未満の入力欄 | 16px 以上にする。iOS Safari がフォーカス時に拡大する |
| ホバーで開くメニュー | クリックで開く。タッチ端末ではホバーが働かない |
| 感嘆符、待機メッセージ、煽り語 | 平叙で何をするかを書く |

意図して残す行には `check-ui-ignore` と書くと、検査から外れます。
外した行の数は Spoke 側で管理してください。Hub の `make allow-budget` と同じく、増やす場合は理由を伴う運用にすると、検査が形骸化しません。

## Spoke での検査手順

```bash
node tools/portable/check-ui/check-ui.mjs --json <画面のソースのディレクトリ>
```

終了コードは、指摘 0 件で 0、1 件以上で 1 です。
Hub の `make test` は、この検査が固定した入力で全 17 規則に反応し、きれいな入力では何も出さないことを確かめます。
Spoke の実際の画面に対する結果は、規則が画面の意図に合っているかを人が見て判断します。
検査スクリプトの指摘件数は兆候で、画面が良くなったかどうかの判定には使いません。
