## このノートの範囲

**技術的な機構はここには書きません。** AWS DataSync のロケーション種別、各 SaaS の管理者 API の呼び出し方、FSx for ONTAP S3 AP のサイズ上限は、すべて一次情報側にあります。

> 一次情報: [SaaS / クラウドストレージから FSx for ONTAP への移行とデータ連携](https://github.com/Yoshiki0705/FSx-for-ONTAP-S3AccessPoints-Serverless-Patterns/blob/main/docs/ja/saas-to-fsx-ontap-migration.md)（[English](https://github.com/Yoshiki0705/FSx-for-ONTAP-S3AccessPoints-Serverless-Patterns/blob/main/docs/en/saas-to-fsx-ontap-migration.md)）

ここに置くのは **計画のどこで何を確定させるか**です。移行元について何を調べ、Assess で何を測り、どこで「移行ではなく再設計」と判断するか。

---

## 結論

**転送方式の検討に入る前に、3 つを確定させてください。**

1. **移行元がストレージエンドポイントを公開しているか。** ここで経路が分かれます。「クラウドストレージ」と一括りにされていても、S3 互換 API を公開しているものと、コラボレーション SaaS は別のカテゴリです
2. **権限の写像先があるか。** SaaS の共有モデルに対応物のない形態（社外リンク共有、期限付き共有）がどれだけあるか。ここが多いと、作業は移行ではなく**権限の再設計**になります
3. **最大ファイルサイズが 50 GiB を超えるか。** 超えるなら S3 AP 経由の投入はできません。書き込み経路の分岐です

**そして、API のレート制限を実測するまで停止時間を確定させないでください。** コラボレーション SaaS からの移行では、差分同期の所要時間をレート制限が支配します。カタログ上の値では見積もれません。

> **Evidence**: `documented` — 事実関係（どの移行元が扱えるか、テナント単位の管理者認可の有無、プライマリストレージ構成の挙動）は一次情報が引く AWS / 各ベンダーの公式ドキュメントに基づきます。
> **確認の順序と Go/No-Go の閾値は実務上の判断であり、検証結果ではありません。** 未確認の項目は「[確認していないこと](#確認していないこと)」に明記しています。

## 1. 移行元の群を判定する

**この 3 点で経路がほぼ決まります。** 順番に意味があり、上から順に候補を絞ります。

| # | 確認すること | 結果が意味すること |
|---|---|---|
| 1 | **そのサービスは S3 互換 API（または Blob / NFS / SMB）を公開しているか** | 公開している → 群 A。DataSync のロケーションとして扱えます。していない → 2 へ |
| 2 | **自ホストの OSS（Nextcloud / ownCloud / Seafile）か** | はい → 3 へ。いいえ（コラボレーション SaaS）→ 群 B。DataSync では扱えず、管理者 API + 自作ワーカーになります |
| 3 | **オブジェクトストレージは「プライマリストレージ」か「外部ストレージ」か** | 外部ストレージ → 群 A として扱えます。**プライマリストレージ → 経路が変わります**（後述） |

### 3 が最も重要です

**プライマリストレージ構成では、バケットを直接コピーしても復元できません。** ファイル名とディレクトリ構造はデータベース側にあり、バケットには識別子（`urn:oid:<id>` 形式）の本文しか入りません。

**そして、この失敗は失敗として現れません。** 転送は成功します。FSx for ONTAP 上に識別子名のファイルが並び、利用者が自分のファイルを開けない、という形で後から判明します。

「移行が終わった」と判断した後に発覚する種類の問題なので、**判定は Assess で必ず済ませてください。** 判定方法は一次情報側にあります。

### 1 でサービス名から即断しないこと

サービス名ではなく、**S3 互換 API の有無で判断してください。** 名前が似ていても別サービスのことがあります（例: Google Cloud Storage は DataSync のソースに含まれますが、Google Drive は含まれません）。

DataSync のソース対応と Bedrock のコネクタ対応は**追加される側に動きます。** 「未対応」と書かれた記述を根拠に方針を決める前に、その時点のドキュメントを引き直してください。

## 2. 群 B ならテナント管理者権限を移行期間中に用意できるか

**これが中央実行の前提条件です。**

コラボレーション SaaS の主要 5 サービス（Microsoft 365 / Google Workspace / Box / Dropbox Business / Egnyte）は、**利用者ごとの OAuth 同意を必要としないテナント単位の管理者認可**を持ちます。つまり運用側で中央から一括実行できます。「利用者にそれぞれ設定させるしかない」という前提は、これらのサービスには当てはまりません。

確認するのは技術的可否ではなく、**組織として権限を発行できるか**です。

| 確認すること | 確認しないまま進めた場合に起きること |
|---|---|
| 移行期間中、テナント全体を読める権限を発行できるか | 発行できないと、中央実行の前提が崩れて計画を作り直します |
| その権限を移行完了後に取り消す手続きがあるか | テナント全体権限が残ります。移行用のアプリケーション登録は高価値の標的です |
| 移行が生む大量の読み取りが、通常時の監査アラートの閾値に触れないか | 移行中にセキュリティ側から停止要請が来ます |
| 代理実行が監査ログにどう記録されるか | 「誰が実行したか」が曖昧なまま大量アクセスの記録が残ります |

**権限は移行期間だけ有効にし、終了後に取り消す前提で設計してください。** これは移行計画の最後のタスクとして明示的に置く項目です。

## 3. Assess フェーズで採取すべき数値

**03-migrate の判断は、これが揃っていないと始まりません。** 01-assess の棚卸しに以下を追加してください。

| # | 採取する数値 | どの判断に使うか |
|---|---|---|
| 1 | 総容量 | 経路の総コスト試算。中継を挟む構成と直行構成のどちらが安いかは容量で逆転します |
| 2 | ファイル数 | 大量小ファイルは転送スループットをメタデータ操作が律速します。分割並列の設計が必要かの判断 |
| 3 | **最大ファイルサイズ** | **50 GiB を超えるかが書き込み経路の分岐です。** 超えるなら S3 AP 経由では投入できません |
| 4 | SaaS ネイティブ形式の割合 | 変換が必要な範囲。変換は不可逆なので「何を正本にするか」の意思決定量に直結します |
| 5 | 外部共有の件数 | 権限写像で対応物がない部分の規模。Go/No-Go の材料になります |
| 6 | バージョン履歴を移行するか | 全履歴を移すと総容量が数倍になります。容量見積もりが変わります |

**3 と 5 は見落としやすく、後から判明すると計画を作り直す項目です。**

数え方そのものの落とし穴（バイトを数えることはファイルを数えることではない）は [容量が余っていても書けなくなる](../../01-assess/notes/counting-bytes-is-not-counting-files.md) にあります。

## 4. Go/No-Go の判断材料

**「移行できるか」ではなく「移行として成立するか」を判断します。**

### 停止条件 1 — 対応物のない共有形態が多い

社外リンク共有、匿名リンク、期限付き共有には、NFS / SMB の ACL に写像先がありません。代替手段（有効期限付きの URL 発行、Transfer Family 経由の配布、ポータル側での共有機能の実装）を**別途設計する**ことになります。

| 件数の規模 | 作業の性質 |
|---|---|
| 少数（例外的な利用） | 移行。個別に代替手段を割り当てられます |
| 多数（業務の主要な使い方） | **移行ではなく再設計。** 転送を検討する前に、共有要件を洗い直す工程が入ります |

**閾値は数値では決められません。** 判断材料は「その共有形態が業務の主要な使い方か、例外か」です。**パイロット（1 部門程度）で権限写像を確定させてから本移行に入る順序**にしてください。データだけ先に移すと、移行直後に全ファイルが管理者のみアクセス可能な状態で置かれます。

### 停止条件 2 — レート制限の実測が終わっていない

**実測が終わるまで停止時間を確定させないでください。** 群 B では差分同期の所要時間を API のレート制限が決めます。帯域からは計算できません。

| 状態 | 表明できること |
|---|---|
| パイロット未実施 | 「経路は決まった。所要時間はパイロットで実測する」 |
| パイロット実施済み | 実測値に基づく見積もり。前提（対象範囲、容量、時期）を併記します |

パイロットの規模は 1 部門・数百 GB 程度で、目的は転送の完了ではなく**レート制限とスループットの実測**です。

### 停止条件 3 — 正本の所在が決まっていない

SaaS ネイティブ形式を変換して移すと、共同編集・コメント・変更履歴が落ちます。**変換は不可逆です。** 「変換して移す」「ネイティブは残して残りを移す」「移さず横断検索だけ実現する」のどれを選ぶかが決まっていない状態では、転送を始めてはいけません。

## 5. そもそも移行が要件か確認する

**バイトを動かさずに横断検索だけ実現する選択肢があります。**

Amazon Bedrock Knowledge Bases のマネージドコネクタは OneDrive / Google Drive / SharePoint に対応し、取得時に ACL による文書単位のフィルタがかかります。FSx for ONTAP を S3 AP 経由のデータソースとして同じナレッジベースに載せれば、移行せずに横断検索が成立します。

用途に応じた選択です。どちらが優れているという話ではありません。

| 目的 | 移行 | 連携のみ |
|---|---|---|
| 横断的な自然言語検索がしたい | 過剰。連携で足ります | 適します |
| NFS / SMB から既存アプリで参照したい | 適します | 満たせません |
| SaaS の契約を終了したい | 適します | 満たせません |
| FSx for ONTAP 側で WORM 保持やランサムウェア対策を効かせたい | 適します | 満たせません |
| 短期間で成果を出したい | 時間がかかります | 早く着手できます |

**連携側の制約も対称に書きます。** 埋め込み生成のためにコンテンツは Bedrock へ渡ります。「移行しないからデータは動かない」は成立しません。リージョン指定とデータ処理の範囲は、移行の場合と同じ基準で評価してください。**コネクタ別の GA / preview 状況は本番採用前に確認が必要です。**

目的が「検索」だけなら、移行の検討に入る前にここを確認してください。

## よくある誤解

| 誤解 | 実際 |
|---|---|
| クラウドストレージなら DataSync で移せる | ストレージエンドポイントを公開しているかで分かれます。S3 互換 API を公開しているものは扱えますが、コラボレーション SaaS は扱えません |
| サービス名で対応可否を判断できる | 名前の似た別サービスがあります。判定基準は S3 互換 API の有無です |
| 一括移行ツールがないので利用者にやらせるしかない | 主要 5 サービスはテナント単位の管理者認可を持ち、中央から一括実行できます。不足しているのは SaaS 側の一括アクセス手段ではありません |
| 自ホスト OSS ならバケットをコピーすれば済む | プライマリストレージ構成では復元できません。**しかも転送は成功するため、失敗として現れません** |
| 移行の工数は転送時間で決まる | 大半は権限モデル・ネイティブ形式・付随データの写像設計です |
| ファイルが移れば業務が移る | バージョン履歴、コメント、共有リンク、ゴミ箱は別途の判断が必要です |
| 帯域から停止時間を計算できる | 群 B ではレート制限が支配します。実測が前提です |
| データだけ先に移して権限は後で整えられる | 移行直後に全ファイルが管理者のみアクセス可能な状態で置かれます。権限写像はパイロットで確定させます |
| 50 GiB を超えるファイルもマルチパートで投入できる | S3 AP 経由では投入できません。NFS / SMB 経由にしてください |
| 移行しなければデータは動かない | 連携でも埋め込み生成のためにコンテンツは外部へ渡ります |

---

## 確認していないこと

**一次情報側で未確認としている項目は、ここでも未確認として扱います。**

- **Amazon AppFlow のコネクタ網羅性**は確認していません。レコード指向で宛先に FSx for ONTAP がないため候補外という判断は変わりませんが、特定のコネクタが存在しないと断言はしていません
- **Amazon Bedrock Knowledge Bases のコネクタ別 GA / preview 状況**は個別に確認が必要です
- **Citrix ShareFile のテナント全体の代理実行**の可否は確認できていません
- **iCloud Drive の法人向け管理者 API** は確認できませんでした。存在しないと断言はしていません
- **商用移行サービスの製品評価はしていません。** 構造上の可否のみです
- 一次情報の DataSync ロケーション対応表と Bedrock コネクタ一覧は **2026-08 時点のスナップショット**です

**リージョン提供状況とコネクタ対応は動きます。** 対応状況を計画書や資料に書く場合は、書く時点で引き直してください。
