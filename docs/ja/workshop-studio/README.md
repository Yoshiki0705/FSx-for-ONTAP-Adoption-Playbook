# Workshop Studio — ハンズオン開催の知見

[🏠 リポジトリトップ](../../../README.md)

AWS Workshop Studio で公開されているワークショップを、コミュニティイベントの持ち時間に合わせて
実施するための知見をまとめます。**公開ワークショップの内容を再掲する場所ではありません。**
本家の手順は本家を読めば足りるので、ここに置くのは本家を読んでも分からないことだけです。

| ここに書くこと | ここに書かないこと |
|---|---|
| 実測した所要時間と、公称値とのずれ | 本家の手順書き写し |
| 時間内に収めるためのモジュール取捨選択とその根拠 | 本家に載っている手順の翻訳 |
| モジュール間の隠れた依存関係 | ワークショップの宣伝文 |
| 自アカウントで実施したときに詰まる箇所 | AWS アカウントの調達方法 |

## シナリオ

| シナリオ | 想定時間 | 題材 |
|---|---|---|
| [EDA ログのゼロコピー分析 — 90 分版](eda-s3-access-points-90min/) | 90 分（イベント全体 2 時間） | NFS で書いた EDA ログを S3 Access Point と Amazon Quick で扱う |
| [Windows ファイルサーバー版 — 90 分版](smb-fileserver-quick-90min/) | 90 分（同上・事前準備が別途必要） | SMB で書いた文書を Windows ID の S3 Access Point と Amazon Quick で扱う |

2 つは同じ構造で題材だけが違います。**準備に時間を割けるなら SMB 版、当日の確実性を優先するなら
EDA ログ版**です。SMB 版は Active Directory が前提になりますが、その作成時間は
Workshop Studio の払い出し時間に吸収できます。

| 横断する資料 | 内容 |
|---|---|
| [本家 18 モジュールとの対応表](module-mapping.md) | どれを実施し何分見込むか、SMB 手順の差し込み位置、環境へのデータの渡し方 5 通り |

## この領域の書き方

ハンズオンの所要時間は「誰がやるか」で大きく変わるため、数値は必ず**測った条件と一緒に**書きます。

- 機械の時間（API 応答、スクリプト実行）と人の時間（説明、画面操作、待ち）を分けて書く
- 公称値をそのまま信用せず、実測値と並べる。ずれていたらずれを書く
- 実測していないモジュールは、実測していないと明示する。埋めない

証拠の扱いは [証拠ポリシー](../evidence-policy.md) と同じ基準です。
