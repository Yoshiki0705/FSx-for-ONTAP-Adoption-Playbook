# FSx for ONTAP の適合条件と適合しない条件

[🏠 リポジトリトップ](../../../README.md) | [Reference](README.md)

---

## この文書の役目

**ファイルストレージ構成をレコメンドするエージェントが、機械的に判定するための条件表です。**

このリポジトリの他の 2 文書とは役目が違います。同じ表を 3 か所に置かないため、重複させていません。

| 文書 | 誰が読むか | 何が書いてあるか |
|---|---|---|
| [ファイルストレージの選択肢の比較](comparison/file-storage-options.md) | **人間** | 7 つの選択肢のトレードオフを対称に。推奨案自身の制約も含みます |
| [どの AWS ファイルストレージかを決める](decision-trees/file-storage-selection.md) | **人間** | 判断の順序。7 終端のうち 4 つは FSx for ONTAP に落ちません |
| **この文書** | **エージェント** | 判定に必要な入力、適合しない条件、**根拠に使ってはいけないもの** |

**「速い」「優れている」という形の記述はありません。** 判定に使えないためです。

> **区分**: `documented` — 条件は AWS 公式ドキュメントの記載に基づきます（2026-09-06 に確認）。出典 URL は [比較表の参照した一次情報](comparison/file-storage-options.md#参照した一次情報) に全項目あります。

## エージェントが集める入力

**下の 6 項目が揃うまで判定しません。** 欠けた項目を既定値で埋めると、埋めた側の想定が判定結果に混ざり、利用者はそれを区別できません。

| # | 入力 | 取りうる値 | 欠けているときの扱い |
|---|---|---|---|
| 1 | 必要なプロトコル | `SMB+NFS 同一データ` / `SMB のみ` / `NFSv3` / `NFSv4 系のみ` / `POSIX 並列` / `ファイル意味論なし` | **判定しない。** 利用者に問う。**これが最も強い制約で、7 択が 1〜2 択になります** |
| 2 | 正本の位置 | `Amazon S3` / `ファイルシステム側` / `オンプレミス` | 判定しない。利用者に問う |
| 3 | 読み書きの比率 | `読み取り中心` / `書き込みが主` | **1 と 2 で結論が出ている場合のみ省略可** |
| 4 | マルチプロトコル要件 | `あり` / `なし` / `将来あり` | **`将来あり` を `なし` として扱わない。** 後から SMB を足せない選択肢があります |
| 5 | 既存 ONTAP 資産 | `あり` / `なし` | 判定しない。**移行の作業量が変わります** |
| 6 | 拠点の位置 | `正本と同一リージョン` / `遠隔・別拠点` | 正本が `Amazon S3` かつ `読み取り中心` のときのみ必須 |

**次の 3 つは入力ではありません。** 判定の後に決めるものなので、これを先に問うと順序が崩れます。

| 判定後に決めるもの | 理由 |
|---|---|
| スループット容量 | 選択肢によって単位も意味も違います |
| 容量 | 最小構成のサイズは選択肢ごとに違います |
| 世代・デプロイタイプ | FSx for ONTAP を選んだ後の判断です。**作成後に変更できません** |

## 適合しない条件

**適合しない条件を先に評価します。** 該当したら FSx for ONTAP を提案しません。

| # | 条件 | 代わりに提案するもの | 判定の根拠 |
|---|---|---|---|
| 1 | プロトコルが `NFSv4 系のみ` かつ マルチプロトコル要件が `なし` かつ 既存 ONTAP 資産が `なし` かつ Windows・ACL・`nconnect` のいずれも不要 | **Amazon EFS** | FSx for ONTAP は SSD 1,024 GiB × HA ペア数 + スループット 384 MBps が下限。Amazon EFS に最小構成はありません |
| 2 | プロトコルが `SMB のみ` かつ マルチプロトコル要件が `なし`（`将来あり` を含まない） | **FSx for Windows File Server** | SSD 32 GiB から。**2 つの制御面を持つ理由がありません** |
| 3 | 正本が `Amazon S3` かつ `読み取り中心` かつ 拠点が `正本と同一リージョン` | **Amazon S3 Files** | 正本を移す必要がありません。**リンク先バケットに S3 バージョニングが必須** |
| 4 | プロトコルが `ファイル意味論なし` | **Amazon S3**（読み取り中心なら Mountpoint for Amazon S3） | Mountpoint は既存ファイルの更新・ディレクトリ削除・シンボリックリンク・ファイルロック・POSIX パーミッションを持ちません |
| 5 | プロトコルが `POSIX 並列` | **FSx for Lustre** | Lustre クライアントが必要で、カーネル版の対応表に縛られます。**Windows は選択肢に入りません** |
| 6 | 正本が `オンプレミス` かつ オンプレミス側に正本を残す | **S3 File Gateway** | AWS が「エンタープライズ NAS の完全な置き換えを意図していない」と明記しています |
| 7 | 共有 1 つ、数十 GiB 規模、単一プロトコル | **Amazon EFS** または **FSx for Windows File Server** | 最小構成のコストが用途に対して過剰です |

**#1 と #2 で `将来あり` の扱いを間違えると、後から作り直しになります。** マルチプロトコルは作成後に足せる場合と足せない場合があり、FSx for Windows File Server は NFS を出せません。

## 適合する条件

**適合しない条件のどれにも該当しない場合に評価します。** 密度を落とさず、なぜ適合するかを書きます。

| # | 条件 | 理由 | 同時に伝えること |
|---|---|---|---|
| 1 | プロトコルが `SMB+NFS 同一データ` | **他に選択肢がありません** | ボリュームのセキュリティスタイルで権限モデルが決まります。**NTFS スタイルでは ID マッピングを止めても SMB アクセスは止まりません** |
| 2 | ファイルとブロックを 1 台から出す | NFS / SMB / iSCSI / NVMe/TCP が同一ファイルシステムから出ます | iSCSI は HA ペア 6 組以下、NVMe/TCP は第 2 世代かつ 6 組以下 |
| 3 | 同じデータを S3 API でも読む | S3 Access Point 経由で届きます | **同一アカウント・同一リージョンの制約があり、アクセスポイントを有効にするとボリューム数の上限が下がります** |
| 4 | スナップショット世代を多く持つ | 別建ての課金項目になりません | **確保済み SSD 容量を消費します。** 満杯になると書き込みが落ちます |
| 5 | 既存 ONTAP 資産が `あり` | SnapMirror と既存の運用手順がそのまま使えます | AD 参加が前提なら、**サービスアカウントの有効性がファイルシステムの生存期間ぶん必要**です |
| 6 | プロトコルが `NFSv3` | Amazon EFS と Amazon S3 Files はどちらも非対応 | S3 File Gateway も NFSv3 に対応します。**正本の位置で選び分けてください** |

**#1 以外は「FSx for ONTAP でなければならない」ではありません。** 適合する理由が別にあるだけです。判定結果を伝えるときに、この区別を落とさないでください。

## 判定を人間に返す条件

**エージェントが決めてはいけないものです。** 該当したら判定を止め、何を決める必要があるかを伝えます。

| 条件 | 理由 |
|---|---|
| **不可逆な設定を含む提案**（SnapLock、Object Lock、Vault Lock、スナップショットロック、`PERMANENTLY_DISABLED`） | **保持期間を名指しした人間の指示なしに提案しません。** 正しく働いている状態が、起こした障害と区別できません |
| デプロイタイプ（Single-AZ / Multi-AZ）と世代 | **作成後に変更できません。** スケールアウトの上限も同時に固定されます |
| 規制・法務・コンプライアンスに関わる判断 | このリポジトリの記述は**一般的な設計上の考慮事項**で、法務判断ではありません |
| 費用の見積り | 料金は改定されます。**現行の料金ページか Price List API から取得し、取得日を添えてください** |
| 入力 1〜6 のいずれかが欠けている | 既定値で埋めると、埋めた側の想定が結果に混ざります |

## 根拠に使ってはいけないもの

**このリポジトリと供出元が明示的に「根拠にするな」と書いている範囲です。**

| 使ってはいけないもの | 理由 |
|---|---|
| **SMB のキャッシュ制御下の読み取り** | **未測定です。** 範囲は [SMB の測定済みの範囲と未測定の範囲](comparison/file-storage-options.md#smb-の測定済みの範囲と未測定の範囲) |
| **SMB の台数試験の数値を 1 つだけ引くこと** | **全台が同じデータを読むかどうかで逆の結論が出ます。** 8 台で伸び続ける表と 4 台で頭打ちになる表が同時に成立しており、どちらも実測です。片方だけを「台数を増やしたときの伸び」として使うと、別の製品の説明になります |
| **SMB の台数試験の数値をベースラインとして扱うこと** | 1 点あたりの定常窓は 180 秒で、6 点を約 40 分の間に連続実行しています。**AWS はネットワーク I/O にクレジット機構があると明記しているため、この窓長ではベースラインとバーストが分離されていません** |
| **SMB の持続書き込みの値を公表値と突き合わせて優劣を判定すること** | 一般則にも例外表にも一致しません。**同じファイルシステム・同じノードの同じ物理ポートで NFS 2,063.00 MB/s、SMB 1,488.03 MB/s です。片方が公表値に近いことは、もう一方を疑う根拠になりません** |
| **SMB Multichannel が有効であることを前提にした数値を、確認せずに使うこと** | **ONTAP では既定無効です。** `dialect=3.1.1` でネゴシエートされていてもチャネルが張られているとは限らず、有効化は既に張られた接続に届きません |
| SMB Multichannel のチャネル数 4 を製品の上限として扱うこと | 設定値を上げても 4 で止まった観測はありますが、**なぜ 4 なのかは確認されていません** |
| NFS と SMB の優劣 | 比較に使える 2 列は**キャッシュ温度が揃っていません** |
| 第 2 世代 6,144 MBps の書き込み上限 | AWS の記載が 2 つあり食い違っています。**このリポジトリでも供出元でも判断していません。** 「公表値の 2 倍出た」の形で使わないでください |
| Amazon EFS の Provisioned スループット 1,024 MiB/s をリージョンの上限とすること | Service Quotas の値で、引き上げ済みのアカウントでは異なります |
| S3 Access Point の対応オペレーション表を「非対応の網羅」として扱うこと | **AWS 自身が partial list と明記しています** |
| Amazon S3 Files の NFSv4.0 対応を断定すること | AWS の 2 ページで記載が食い違います。表は狭いほう（v4.1 / v4.2）を採っています |
| 「Amazon EFS は SMB 非対応」を独立の主張として使うこと | **その直接の記述はありません。** 根拠は Windows を実行する EC2 からのマウントが非対応であることです |

## 確度を表す語の読み替え禁止

**このリポジトリと供出元は、それぞれ 4 段階を使います。語が違うので対応を書きます。**

| このリポジトリ（frontmatter の `evidence`） | 意味 |
|---|---|
| `verified` | 著者が実環境で再現した。日付と環境が併記されています |
| `documented` | AWS またはベンダーのドキュメントに記載がある。**実機では確かめていません** |
| `field-observation` | 現場で 1 回観測した。**再現していません。一般則として扱わないでください** |
| `hypothesis` | 推論による見込み。**未検証です** |

| 供出元（[S3-Burst-on-ONTAP-Files](https://github.com/Yoshiki0705/S3-Burst-on-ONTAP-Files/blob/main/docs/ja/verification-status.md)） | 意味 |
|---|---|
| 検証済み | 実環境で再現した。環境を併記 |
| ドキュメント記載 | ドキュメントに記載がある。実機では確かめていない |
| 未検証 | 確かめていない。記載はあるが実機で追っていない、または記載自体がない |
| **未確認** | **`公開ドキュメントに記載を見つけられていない。「できない」ではない`** |

**「未確認」を `cannot` / `not supported` / 「できない」に読み替えないでください。** これは記載を見つけられていないという、**ドキュメントについての記述**です。機能の不在ではありません。

**同じ理由で、列挙の不在を非対応と断定しないでください。** Amazon EFS の NFSv4.2 は「非対応」と書かれておらず、対応プロトコルの列挙に無いだけです。**機能は後から追加されます。** 古い制約を断言し続けるのが、この種の判定でいちばん害の大きい失敗です。

## 数値の扱い

| 規則 | 理由 |
|---|---|
| **数値を環境から切り離さない** | 実測値はすべて供出元のもので、測定日・リージョン・ONTAP 版・世代・スループット指定値・SSD・IOPS・オブジェクトサイズ・並列度が本文に併記されています |
| **同じ数値を同じ原因に束ねない** | Amazon EFS の 499.79 MB/s は EC2 の 1 フロー上限ではなく、documented なクライアント単位クォータ 500 MiBps に一致します。**近い数値は同じ原因の証拠になりません** |
| **単一接続の値からファイルシステムの上限を外挿しない** | 8 台 128 接続では ONTAP 物理ポートの累積カウンタ差分が 102 Gbps に達しています |
| **1 つの数字でファイルシステムのスループットを述べない** | 接続数・データ共有の有無・キャッシュの温まり方で変わります。同一構成の 2 回測定で 45% 振れた記録があります |
| **サンプル実行と本番見積りを分ける** | 短時間の試験はバースト性能を測ります。クレジット残高を記録していない測定は再現しません |

## 出力に必ず添えること

**判定結果だけを返すと、利用者は根拠を検証できません。**

| 添えるもの | 具体例 |
|---|---|
| 提案しなかった選択肢と、その理由 | 「マルチプロトコル要件が `なし` なので FSx for Windows File Server を選びました。将来 NFS も出す予定があれば結論が変わります」 |
| 判定に使った入力 6 項目の値 | 利用者が誤りを見つけられる形にします |
| 確度 | ドキュメント記載か、実測か、未測定か |
| 未測定の範囲 | SMB の 3 項目に触れる提案なら明示します |
| 次に読む文書 | [決定木](decision-trees/file-storage-selection.md) と [比較表](comparison/file-storage-options.md) |
